## Context

运行模块一次只能为一条 `Flow` 创建 `Run`；执行器按任务表领取单条 `replay`。造数需要连续多条已确认用例，但不改 Worker 协议。见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 套件落库（站点内、有序成员、可多套件共享同一用例）
- 勾选运行与套件运行共用同一批次状态机：只入队当前条，通过再入队下一条
- 控制台能勾选、存套件、跑套件，并跟到当前这一条运行

**Non-Goals:**

- 同一浏览器会话连续回放
- 用例之间传递变量
- 失败后继续跑完
- 套件进 CI 门禁

## Decisions

1. **批次是一等实体，套件只是模板**  
   勾选运行没有套件也可以开批次。`Suite` 存定义；`Batch` 存这一次执行（成员快照、当前下标、当前 `run_id`）。  
   备选：把 N 条 Run 一次性全部 `queued`。否决：失败即停无法阻止 Worker 领走后面的任务。

2. **下一条由 `complete_run` 衔接**  
   不依赖浏览器保持打开。前一条 `passed` 才创建下一条 Run 并 `notify_new_job`。  
   备选：前端 SSE 结束后再 POST 下一条。否决：关页就会断链。

3. **成员存在 `flow_ids` JSON 数组**  
   第一版无独立成员表。顺序即数组顺序。  
   备选：关联表。推迟到需要同一套件内重复同一用例或成员级元数据时再拆。

4. **仅 `reviewed` / `golden` / `active` 可入组、可跑**  
   启动批次时再校验一遍；中途被退回草稿则批次失败即停（与运行失败同等处理）。

5. **`Run.batch_id` 可空**  
   单条「运行所选流程」行为不变。历史列表不必改交互，批次信息可挂在 summary 或 Run 字段上供控制台订阅下一条。

## Risks / Trade-offs

- [每条用例独立开浏览器、重新登录] → 第一版接受；同会话是后续能力
- [SQLite 旧库 `run` 表缺 `batch_id`] → `init_db` 补列，与 `stop_requested` 同一套路
- [套件成员被删或退回草稿] → 启动时 409；执行中下一条校验失败则批次失败

## Migration Plan

新表 `suite`、`batch` 由 `create_all` 创建；`run.batch_id` / `run.batch_index` 启动时补列。回滚：停用套件 API 与控制台按钮，旧单条运行不受影响。

## Open Questions

无。失败即停、勾选可先不存套件、命名用「套件」已在对话中确认。
