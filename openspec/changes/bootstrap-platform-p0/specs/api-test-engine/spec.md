## Purpose

提供接口层回归能力：把抓到的真实流量或手工录入的请求整理成可重复执行的请求集，跑批并按断言判定成败。它是日常回归里最便宜、最稳定的一层。

## ADDED Requirements

### Requirement: 从 HAR 导入请求集

平台 SHALL 支持上传 HAR 文件并从中生成请求集，允许按 URL 模式筛选要保留的请求。

#### Scenario: 导入并筛选

- **WHEN** 使用者上传一份 HAR 并指定只保留某些 URL 模式的请求
- **THEN** 平台生成请求集，其中仅包含匹配的请求，且每个请求保留方法、URL、头、请求体

#### Scenario: 导入时脱敏

- **WHEN** HAR 中包含鉴权头或凭证字段
- **THEN** 生成的请求集将其替换为变量引用，不保存明文

### Requirement: 请求集跑批

执行器 SHALL 按顺序重放请求集并汇总通过率；单个请求失败 SHALL NOT 中断整批执行，除非该请求被显式标记为前置依赖。

#### Scenario: 批量执行出结果

- **WHEN** 执行一个包含多个请求的请求集
- **THEN** 运行结束后给出每个请求的成败、耗时与整批通过率

#### Scenario: 前置依赖失败时跳过后继

- **WHEN** 某个被标记为前置依赖的请求失败
- **THEN** 依赖它的后继请求被标记为跳过而非失败

### Requirement: 业务错误体判定

断言 SHALL 支持响应体级别的失败判定：当 HTTP 状态码为 2xx 但响应体中存在非空 `errors` 字段或站点配置的业务错误标记时，该请求 SHALL 判为失败。

#### Scenario: HTTP 200 但业务失败

- **WHEN** 某请求返回 HTTP 200 且响应体为 `{"errors": [{"message": "..."}]}`
- **THEN** 该请求判为失败，并在结果中给出错误消息

#### Scenario: 响应不是 JSON

- **WHEN** 某接口本应返回 JSON 却返回了 HTML 错误页
- **THEN** 该请求判为失败，原因标明响应格式不符预期

### Requirement: 断言表达式

平台 SHALL 支持对状态码、JSON 路径取值、响应文本包含关系的断言，并 SHALL 在失败时给出实际值与期望值。

#### Scenario: JSON 路径断言失败可诊断

- **WHEN** 断言某 JSON 路径应等于指定值但实际不同
- **THEN** 结果中同时给出该路径、期望值与实际值
