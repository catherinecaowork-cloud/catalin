## Purpose

在被测页面里植入一段与业务无关的探针，捕获前端静默错误与「表面正常、底层请求失败」的情况。这类问题接口测试测不到、人工点页面也看不出来。

## ADDED Requirements

### Requirement: 探针自动注入且跨导航生效

执行器 SHALL 在浏览器上下文层面注入探针，使其对该上下文中的所有页面与后续导航自动生效，无需按页重复注入；重复注入 SHALL 不产生重复计数。

#### Scenario: 单页应用切换路由后仍生效

- **WHEN** 在单页应用中连续切换多个路由
- **THEN** 每个路由下产生的前端错误都能被同一个探针捕获

#### Scenario: 整页刷新后仍生效

- **WHEN** 页面发生整页刷新或跳转到同站另一页面
- **THEN** 探针仍处于激活状态并继续采集

### Requirement: 前端错误采集

探针 SHALL 采集控制台错误、未捕获的运行时错误与未处理的 Promise 拒绝，并保留可定位的错误摘要。

#### Scenario: 未处理的 Promise 拒绝被记录

- **WHEN** 页面中产生一个未处理的 Promise 拒绝
- **THEN** 该错误出现在页面体检结果中，包含错误消息摘要

### Requirement: 请求级失败检测

探针 SHALL 检测响应状态正常但内容表示失败的请求：包括响应体含非空 `errors` 字段，以及期望 JSON 却返回非 JSON 内容；检测范围 SHALL 可按站点配置的 URL 模式限定，默认不限定于特定后端框架。

#### Scenario: 页面视觉正常但请求失败

- **WHEN** 页面渲染完整、无错误提示，但某接口返回 HTTP 200 且响应体含非空 `errors`
- **THEN** 页面体检结果报告该失败，运行被判定为发现异常

#### Scenario: 返回 HTML 错误页

- **WHEN** 某接口本应返回 JSON 却返回 HTML
- **THEN** 页面体检结果报告响应格式异常

### Requirement: 页面体检可独立调用且零模型成本

页面体检 SHALL 可在不调用任何语言模型的前提下执行，并返回结构化结果（错误计数、失败请求、加载中状态、空数据提示）。

#### Scenario: 回归中批量体检

- **WHEN** 在一次回归运行中对多个页面依次执行页面体检
- **THEN** 每个页面都得到结构化体检结果，且整个过程不产生模型调用

### Requirement: 框架专用规则可插拔

UI 框架相关的判定规则（错误提示组件、加载指示器、表格结构、空态文案）SHALL 由站点适配器提供；核心探针 SHALL NOT 依赖特定 UI 框架的类名。

#### Scenario: 更换站点适配器

- **WHEN** 同一段探针用于使用不同 UI 框架的两个站点
- **THEN** 通过更换适配器即可正确识别各自的错误提示与表格结构，探针核心代码不变
