## Why

弹窗、下拉、日期浮层内的元素会**偶发**定位失败或点击无效——同一条用例这次过、下次不过。根因不在用例脚本，在定位子系统本身，且已逐处定位：

- 候选匹配取 `.first`，但 Ant Design / Element UI 会在 DOM 里保留**隐藏副本**（旧面板不销毁）。`.first` 正好命中隐藏的那份，可见性检查因此为假，整个候选被跳过——同一层里那个**可见**的元素从未被检查。回放的两条解析路径（立即尝试、等待重试）都这么写。
- 解析出候选后只点一次。点不动就直接失败，不回退到下一个候选。
- 原生点击失败后用 `force=True` 兜底，绕过遮挡检查：点错了也报通过。
- 「浮层面板」在仓库里有 **5 份**互不相同的通用定义（3 份在厂商适配器、2 份在录制脚本里），「下拉选项」有 2 份。录制端与回放端各用各的，命中范围已经不一致。
- 浮层没打开导致的未命中，会被当成「定位漂移」：本轮后续步骤不再尝试那个候选，并且打包成修补任务**建议删掉**它。使用者照单确认，好候选就被永久删掉。于是这个缺陷会随时间反向侵蚀已录好的流程。

使用者看到的现象是「时不时找不到元素 / 点不到」，无法复现、无法归因——因为失败被记成偶发，且下一次可能已经把好候选删了。

## What Changes

- 候选匹配从「取第一个匹配再判可见」改为「在有界范围内取**第一个可见**匹配」，两条解析路径统一
- 点击失败时按候选顺序**回退**到下一个候选，直到候选成功、候选耗尽或步骤超时
- 去掉 `force=True` 兜底；动作执行后必须确认生效，确认不了报失败而不是通过
- 「浮层面板」与「下拉选项」的选择器收敛为**单一来源**，录制端与回放端共用；先修掉已漂移的 5 份差异
- 通用件（Ant Design / Element UI）从厂商适配器目录移回执行器，厂商目录只留厂商特例
- 失败原因分类：只有「目标确实变了」才允许判定定位漂移并固化候选；「浮层未打开 / 被遮挡」不得产生漂移判定、不得删候选
- 失败报告能区分「没找到」「找到但点不到」「点了没生效」三类

**不含 iframe**：iframe 内元素是新增能力不是缺陷修复，另开 change。本次只在规格里明确记为不支持。

## Capabilities

### New Capabilities

- `locator-resolution`: 候选解析与动作执行——可见性收敛、候选回退、动作生效确认、失败原因分类、浮层选择器单一来源

### Modified Capabilities

- `locator-heal`: 漂移判定的前提收窄——只有目标确实变化才判定漂移，浮层未打开等环境原因不得触发候选固化

## Impact

- **执行器**：`packages/executor/autotest_executor/browser/` 的 `locator.py`（两条解析路径）、`actions.py`（点击与等待）、`locator_candidates.js`（选择器来源）
- **协议**：`packages/protocol/autotest_protocol/dsl.py` 的候选固化逻辑（失败原因分类）
- **适配器**：`packages/adapters/autotest_adapters/oinone/selectors.py` 的通用件迁出
- **控制面**：`domain/heal.py` 的修补任务构造（不再为环境原因生成条目）；运行结论的失败原因字段
- **使用者可见**：浮层用例重复执行不再偶发失败；失败时能看到属于哪一类
- **未纳入**：iframe 支持；不改定位候选的稳定性排序（`dsl.py` 的 `CANDIDATE_STABILITY`）
