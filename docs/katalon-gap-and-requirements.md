# 对标 Katalon：差距与需求来源

> 日期：2026-09-20  
> 用途：把 Katalon Studio 的产品分层对照成我们的需求来源。排期仍服从 `platform-restructure-plan.md`（内网团队版；不取云端多租户、Groovy、Mobile）。  
> 对照来源：[初识 Katalon 专栏](https://zhuanlan.zhihu.com/p/367031776)（Tests Explorer、Record Web、Spy Web、Manual/Script、对象库、套件与数据）。知乎原文抓取受限时，以同题「初识 Katalon Studio」的界面/目录解说为准。

Katalon 是「**对象库为中心的桌面 IDE**」：录制 / Spy 把控件写入对象库，用例引用对象，再用数据文件和套件去跑。

我们现在是「**录一次轨迹就能回放的 Web 控制台**」：Explorer、录制、回放、套件、环境导入已经像；对象库、Spy、数据驱动、检查点、接口引擎、CI 闸门还没有。

---

## 1. 已经接近（保留，继续打磨）

这些是需求已落地的能力，不是下一期新开项。缺口只在体验与验收，不在「有没有」。

| 来源里的 Katalon | 我们 | 需求含义 |
| --- | --- | --- |
| 浅色 IDE：工具栏、Tests Explorer、中栏、底栏 | 外壳已按这个做（树、搜索、右键、底栏输出/步骤/告警） | **取的是这层壳**；不做成可编程通用 IDE（见 §3.3） |
| Test Cases 树；Record Web 录制 / 回放 | 开窗录制 → 结构化步骤 → 真浏览器回放 | 回放的是 DSL，不是坐标或 Selenium 脚本 |
| 录出步骤可读：关键字 + 目标 | `goto` / `click` / `fill` / `select` / `assert` 等原语 | 无代码优先；一步一个动作 |
| Manual 视图改步骤、改等待 | 步骤表可编辑 | 不提供 Groovy Script 视图 |
| Test Suites 按序执行 | 套件 / 批次、失败即停 | 回归以套件为单位 |
| 多环境 | 站点即环境；可跨环境导入 | 福瑞丝已验证导入「新建款式」回放 |
| 编码少的人也能用 | 录制 + 确认保存；日常回归零模型调用 | AI 只在录完编译 / 观察时介入 |

---

## 2. 形似但不是同一件（不要当成已满足）

排期或验收时禁止用这些条目勾掉 Katalon 对等需求。

| 来源里的 | 我们实际是 | 真正还缺的需求 |
| --- | --- | --- |
| Profiles | 站点 / 环境 | 不是 Katalon 那套执行配置文件（浏览器组合、全局变量集） |
| Keywords 面板拖进用例 | 动作写在步骤 DSL 里 | 没有关键字工具集、不能自定义 Keyword |
| Variables 页 | `{{unique}}` / `{{now}}` 等模板 | 没有用例级变量表、没有外部数据绑定 |
| Reports / Log Viewer | SSE 直播 + 运行历史 | 没有独立报告工程、没有导出报告包 |
| 桌面 `katalon.exe` | 浏览器控制台 + 本机 Worker | 安装形态不同；内网 Worker 长轮询是有意差异 |

## 3. 需求池：来源有、我们还没有

下列条目是**需求来源**，不是本期施工单。已拍板进下一期的标出来；定盘明确不取的单独列出。

### 3.1 下一期（已拍板）

| ID | 来源能力 | 需求陈述 | 验收直觉 |
| --- | --- | --- | --- |
| K-REC | 真站 Record Web 闭环 | 在真实站点现录一条业务（如新建款式），观察者/编译自证后保存，二次回放仍过 | 不是导入已有脚本再跑 |
| K-OR | Object Repository | 控件登记一次，多条用例引用；定位从「贴在步骤上」改为「引用对象」 | 改一处对象，引用它的用例一起好 |
| K-SPY | Spy Web | 可视化捕捉页面元素并写入对象库，供编写用例时引用 | 可不经完整录制也能入库 |
| K-L1 | API 测试 | 导 HAR / OpenAPI 成请求集，变量提取、断言（含 200+`errors` 判失败），登录态与 UI 共用 | 不点页面也能回归接口 |
| K-CI | CI/CD 闸门 | 仅 `active` 流程进流水线；失败非零退出；产物回传平台 | 能卡住发布，而不只是人在控制台点运行 |
| K-DD | Data Files | 测试数据与步骤分离；Excel / CSV 等作为数据源，步骤用参数引用 | 同一脚本换数据能跑多组 |
| K-CK | Checkpoints | 检查点作为可复用资产（或黄金跑基线），不只是步骤里的 `assert` | 能对照基线，而不是每次手写断言 |

对象库是中心：**录制和 Spy 为对象库服务**，不为「这一次点击」服务。自愈修对象，不修散落在各步骤里的选择器。

**施工顺序**（2026-10-12 排定。上表是需求来源，下面才是顺序——两者不是一回事）：

0. **前置（不是 Katalon 对等需求）**：change `restructure-debt`、`locator-popup-fix`。
   浮层内元素偶发定位失败会让 **K-REC 的现录验收结果不可信**——录出来的流程过不过，取决于运气。
1. **K-REC** — 录制-回放闭环不成立，后面全是空中楼阁。
2. **K-CI（最小版）** — 有了闭环才谈得上「卡住发布」。必须排在 1 之后、且排在浮层缺陷修复之后：缺陷没修时闸门只会天天红，红了就没人看了。
   最小版**不含产物回传平台**，只做「跑 `active` 流程 + 失败非零退出」，见 change `ci-daily-gate`。
3. **K-OR + K-SPY** — 对象库是中心，Spy 为它服务，两者一起做。
4. **K-L1（先只做导 HAR）** — 独立于 UI 线，可与 3 并行。
5. **K-DD、K-CK** — **暂缓**：等前面有稳定回归集，再谈数据驱动与检查点。

### 3.2 更后 / 仅在有明确客户时再开

| ID | 来源能力 | 说明 |
| --- | --- | --- |
| K-KW | 自定义 Keyword / 关键字面板 | DSL 原语覆盖日常操作后再考虑用户扩展 |
| K-VAR | 用例 Variables 编辑页 | 可与 K-DD 一起做 |
| K-RPT | 独立 Reports 工程 | 直播和历史先够用；导出报告另开 |
| K-SUITE-COL | Test Suite Collection、多浏览器矩阵 | 套件已有；浏览器继续锁 Playwright Chromium |
| K-LISTEN | Test Listeners / 导入 JAR | 与「不做成通用 IDE」冲突，默认不做 |

### 3.3 明确不取（不要写进排期）

来源文章里有、定盘已否决：

- Eclipse **产品平台**（桌面 RCP、插件 / JAR、Perspective）。界面已经是 Katalon/Eclipse 式信息架构，那是有意取的，不是这项
- XPath 作为第一定位策略（选择器仍以稳定属性 / 角色为主）
- Selenium + Groovy / Java 脚本视图
- Mobile / Appium / Spy Mobile
- TestOps / TestCloud、JIRA / qTest 云端集成
- 生产流量挖掘（TrueTest）
- 验证码、SSO（登录方式不支持则明确失败）

**必须保留、比 Katalon 强的差异**（实现时不能为了「更像」而丢掉）：

- 环境即站点，跨环境靠导入，不把多环境拍平
- 日常回归零模型调用
- 选值「合法即可」，不复刻某次下拉文案
- Worker 单向长轮询，适配内网 / NAT

## 4. 怎么用这份文档

1. 新开 OpenSpec change 时，需求从 **§3.1** 的 ID 引用（例如 `K-OR`），不要从 Katalon 功能清单直接开抄。
2. 验收用「需求陈述 / 验收直觉」，不要用「界面长得像」。
3. 和 `docs/p1.2-ai-observer-plan.md` 的关系：观察者是「认识页面再写脚本」的第一版；**对象库（K-OR）才是控件跨用例复用**。观察者验收（真站现录）是 K-REC，不代替 K-OR。
4. 和 `docs/ui-katalon-redesign-plan.md` 的关系：那是外壳换肤。本文是产品能力差距。基准截图按 UI 变更持续更新，不是本需求池的一条。
