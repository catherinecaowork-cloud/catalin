# P1.2 第一版：AI 观察者（认识页面，再写脚本）

这是交接文档。现有 `docs/p1.2-ai-compiler-plan.md` 做的是 **Compiler：录完后润色**（不能改点击骨架）。
本篇是同一条 P1.2 线上的**观察者第一版**：录制过程中认识页面，Playwright 轨迹只是一次样例，
回放脚本由观察者编写。

OpenSpec：`openspec/changes/ai-observer-p1-2/`。上层叙事见 `docs/p1-record-heal-chat.md` §1。

---

## 0. 你要理解的一句话

人手点一遍，系统**不是**学会「再点一模一样的 Gucci / 155」。
系统要学会：**这个页面有哪些字段、下拉是什么组件、这种组件怎么用、选值时随便选一个合法的就行。**
那一次点击只证明「人是这么走完业务流程的」。

```
你开窗操作（样例）          执行器观察快照（认识原料）
        │                            │
        └────────────┬───────────────┘
                     ▼
              AI 观察者编写 DSL
                     │
                     ▼
           无头回放自证 → 保存 → 日常回归零模型
```

---

## 1. 和「Compiler 润色」的差别

| | 已落地的 Compiler | 本篇观察者第一版 |
|---|---|---|
| 何时用模型 | 录制**结束之后** | 结束时编写；录制**当中**持续采集观察 |
| 录制产物 | 几乎就是脚本 | **样例轨迹**，不等于脚本 |
| 模型权限 | 只能改 label / phase / value / 断言 | **允许改写** action、target、选择策略 |
| 下拉 / 尺码 | 容易写死你点过的那一项 | 写成组件用法 + **任选合法项** |
| 失败 | 回退 P1.1 步骤 | 回退样例；也可再走润色路径 |

日常回归仍然**零模型调用**。观察者只在这次录制会话的编写（及最多 3 轮重写）里用网关。

---

## 2. 三条红线（继承）

| 红线 | 本篇怎么守 |
| --- | --- |
| **控制面不装浏览器** | 快照在执行器采；观察者编写在控制面 |
| **执行器不连库、不调模型** | Worker 只上报脱敏快照 |
| **日常回归零模型** | 保存下来的是 DSL；回放引擎按 `choose_mode` 任选 |

---

## 3. 第一版范围

做：

1. 开窗录制时，在导航完成、弹层开合、表单出现时上报**字段库存**（层、label、控件种类、定位摘要、是否必填）
2. 控制台录制中能看到「已认识」清单（第一版用确定性识别，不必每帧调模型）
3. 停录后：意图 + 全部快照 + 样例轨迹 → 观察者输出**页面模型 + DSL**
4. 选择类步骤默认任选 / 能搜则搜否则第一项；编码类仍 `{{unique}}`
5. 编写结果必须 DSL 合法并自动无头回放；失败最多 3 轮，然后降级
6. 页面模型随流程保存；同站点下次录制可当输入（**没有**独立元素库页面）

不做（第一版）：

- 边点边让模型改脚本
- 全站对象库管理 UI
- 跨环境自动对齐「这是同一个品牌字段」
- 用视觉像素对比当主识别
- 替换 Playwright 录制器（样例仍要录）

## 4. 角色怎么拆

```
┌─────────────┐     快照 / 样例事件      ┌──────────────┐
│ 执行器      │ ─────────────────────► │ 控制面        │
│ 开窗+注入   │                         │ 合并页面认识  │
│ 不调模型    │                         │ 结束：观察者  │
└─────────────┘                         │ 编写 DSL      │
                                        └──────┬───────┘
                                               │ 验证回放任务
                                               ▼
                                        ┌──────────────┐
                                        │ 执行器无头跑 │
                                        └──────────────┘
```

**观察者**不是再派一个浏览器去点。它吃的是结构化观察 + 你那一次操作样例，吐的是回放引擎已经会跑的步骤。

控件「怎么用」第一版写进页面模型（打开方式、选择策略），步骤落在现有 `choose` / `fill` / `click` 上，不新造动作原语。

---

## 5. 选值：随便选一个

样例里点了「155」，回放脚本**不得**把「必须 155」当成契约，除非意图明确要求该主数据。

回放已有能力（本篇要求观察者**写出来**，而不是靠人改）：

- 能搜的下拉：搜不到用第一条
- 尺码 / Tab / 面板：当前有啥选啥，选一个就行
- 非必填且面板空：跳过；必填且完全没选项：失败

唯一性输入（款式编码）相反：不能随便抄样例字符串，要用 `{{unique:key}}`。

---

## 6. 建议落地顺序（对应 OpenSpec tasks）

1. 协议：观察快照、页面模型、`sample_steps` / `observer_steps`
2. 执行器上报快照
3. 控制面合并认识、随流程保存
4. 观察者编写契约（可改骨架）+ 自测
5. 接现有编译验证状态机与降级
6. 控制台：认识清单 + 双栏脚本
7. 真实站点验收：新建款式不写死品牌/尺码，二次回放仍过

自测入口（实现时补）：`scripts/selftest_ai_observer.py`。

---

## 7. 配置

沿用控制台 AI 配置 / `ANTHROPIC_*`。无网关时：只采集观察清单，编写跳过，保存样例草稿（与现在无 Compiler 时类似）。

视觉截图送模型：沿用 `ATP_AI_VISION_ENABLED`，默认关，不挡第一版。

---

## 8. 验收口诀

- 录制中能看到已认识的字段/组件，不是只有步数在涨
- 确认页默认是观察者脚本，能翻到样例轨迹
- 回放可以选和录制时不一样的下拉项，流程仍算通过
- 保存后再跑，不再调模型
