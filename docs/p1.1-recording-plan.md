# P1.1 实施计划：录制回放（不含 AI）

这是一份交接文档，给接手实现的人/模型看。目标是**你操作一遍，系统记住，之后能重放**。
这一期**不接大模型**，全部用确定性规则——模型不可用时录制回放仍然要能工作，
AI 编译（P1.2）是在这个底座之上加一层，不是替代它。

上层设计见 `docs/p1-record-heal-chat.md`。本文只讲怎么实现。

## 0. 先读这些，否则会白干

### 0.1 三条红线

| 红线 | 后果 |
| --- | --- |
| **控制面不装浏览器、不访问被测站点** | 控制面要能塞进不带浏览器的容器。「打开页面」这类事一律派任务给执行器 |
| **执行器不连数据库** | job 必须自包含；凭证按引用换取，只在内存解密 |
| **平台不反向连接执行器** | 只有执行器单向长轮询。被测系统在内网、值班机在 NAT 后 |

## 1. 已完成的部分

这两个文件已经写好，**实现时直接用，不要重写**。

### 1.1 `browser/locator_candidates.js`

装两个全局函数，幂等：

```js
window.__atpDescribe(el, roleOverride?) → { candidates: [{kind, value, name?}, ...] }
window.__atpContext(el) → { dialog, label, in_table_row, page_title, url }
```

`kind` 取值与 `dsl.py` 的 `CandidateKind` 一一对应：`testid / role / label / placeholder / text / css`。
排序由 Python 侧按稳定性做，JS 不管顺序。

**踩点（`onboarding.py`）和录制共用这一份。** 两处各写一套迟早漂移，
届时录制算出的定位和回放找的对不上，会以「偶发失败」的形式表现出来，极难查。
`onboarding.py` 目前还内嵌着一份自己的 describe，**本期应顺手改成引用这个共享文件**。

### 1.2 `browser/recorder.js`

通过 `add_init_script` 注入。要点：

- 事件**不在页面里攒**，通过 `window.__atpEmit(payload)` 直接推给 Python
- 输入合并已在 JS 侧完成：连续 `input` 事件按元素合并，失焦或静默 600ms 产出**一条** `fill`
- 用 **capture 阶段**监听（框架常在冒泡阶段做事件代理并阻止传播）
- 页面右上角有悬浮条，显示已录步数 + 「结束录制」按钮；录制器自身的操作被过滤掉
- 单页应用可能整块重绘 body，悬浮条每秒自愈一次
- 检测到拖拽 / canvas / 文件上传时发 `unsupported` 事件，**不装作录上了**

推给 Python 的事件形状：

```jsonc
{ "type": "click",   "target": {...}, "context": {...}, "text": "保存",  "ts": 1234, "url": "..." }
{ "type": "fill",    "target": {...}, "context": {...}, "value": "款式A", "ts": ..., "url": "..." }
{ "type": "select",  "target": {...}, "context": {...}, "value": "1", "text": "上衣", ... }
{ "type": "press",   "target": {...}, "context": {...}, "key": "Enter", ... }
{ "type": "unsupported", "reason": "拖拽操作", "context": {...}, ... }
{ "type": "stop", ... }
```

暴露给 Python 回写步数：`window.__atpRecorder.setCount(n)`。

### 任务 2：编译器（确定性清洗）

**新建**：`packages/executor/autotest_executor/compiler.py`

唯一入口：

```python
def compile_events(
    events: list[dict], start_url: str
) -> tuple[list[dict], list[str]]:
    """原始事件 → 步骤草稿 + 需要人工留意的提示"""
```

返回的步骤是 **dict 而不是 `Step` 对象**，因为要先交给人在控制台上编辑，
保存时才做 DSL 校验。

#### 清洗规则（只有三条，都要能一句话说清）

1. 同一元素 **150ms** 内的重复点击，只保留一次
2. 点击之后紧接着在**同一元素**上输入 → 丢掉那次点击（进输入框的点击是噪声）
3. `unsupported` 事件不产出步骤，转成提示文案

判断「同一元素」用 target 的**第一个候选**比较 kind+value。

输入合并已在 JS 侧做完，这里不要重复处理。

#### 候选清理

- 按 `(kind, value)` 去重（`cssPath` 可能和 `#id` 撞车）
- 最多保留 4 个，多了没意义
- 丢掉值为 `None` 的字段（`Candidate` 模型里 `name` 可选）

#### 步骤生成

第一步固定是 `goto start_url`，label「打开起始页」。

| 事件 | 动作 | label 规则 |
| --- | --- | --- |
| click | `click` | `{弹窗前缀}点击「{按钮文本}」` |
| fill | `fill` | `{弹窗前缀}填写「{字段名}」` |
| select | `select` | `{弹窗前缀}选择「{字段名}」为 {显示文本}` |
| press Enter | `click` | `{弹窗前缀}回车提交`（DSL 没有独立按键动作，回车通常等价于提交） |

- **弹窗前缀**：`context.dialog` 有值时为 `在「新增款式」弹窗：`，否则空
- **字段名**：优先 `context.label`，其次 target 里的 `placeholder`/`label` 候选，兜底「输入框」
- **按钮文本**：优先事件的 `text`，其次 `text`/`label`/`placeholder` 候选或 `role` 的 name，兜底「元素」

#### mutating 标记

`fill` 和 `select` 一律 `mutating=True`。`click` 的按钮文本命中下列词时标记为 `True`：

```
保存 提交 确定 确认 新增 新建 添加 删除 移除 启用 禁用 发布 归档 导入 生成 创建
save submit create delete confirm
```

这是启发式，所以**确认界面上必须能改**。它的作用是让 `dry_run` 能跳过写操作。

#### 边界

- 一条操作都没录到时，提示里加一句「除了打开页面之外没录到任何操作」

**验证**：写一个 `scripts/selftest_compiler.py`，喂一段构造的事件流，断言：
重复点击被合并、进输入框的点击被丢掉、`unsupported` 变成提示、mutating 标记正确。
这个自测**必须有**，因为清洗规则是后面所有东西的地基。

### 任务 3：录制执行器

**新建**：`packages/executor/autotest_executor/recorder.py`，类 `RecordExecutor`。

参考 `inspector.py` 和 `runner.py` 的写法（事件上报、产物上传、complete 的形状）。

#### 执行顺序（顺序错了会出问题，照抄）

```python
1. session.start(cookies, headers)            # 必须 headed
2. 如果 auth.type == "form"：
       用 ActionRunner 跑 form_login_steps()   # 登录过程也上报事件，控制台能看到
3. page.goto(登录后的起始页)
4. wait_for_app_ready(page)                    # 单页应用要等渲染
5. context.expose_binding("__atpEmit", handler)
6. context.add_init_script(locator_js + "\n" + recorder_js)   # 管后续导航
7. page.evaluate(locator_js); page.evaluate(recorder_js)      # 管当前这一页
8. 循环等待，直到 stop
9. compile_events(...) → complete(summary)
```

**第 5 步必须在第 7 步之前**：`recorder.js` 一装上就会调 `window.__atpEmit`，
binding 还没注册的话事件直接丢。

**第 6 步和第 7 步都要**：`add_init_script` 只对**后续**导航生效，当前这一页得手动 evaluate。

#### 为什么用 expose_binding 而不是轮询页面缓冲

整页导航会清空 `window`。靠页面内数组攒事件、Python 定时来取，导航前那一小段必然丢。
`expose_binding` 注册在 **context** 上，跨导航存活，事件产生即推送。

#### 等待循环

```python
while not self._stopped:
    if page.is_closed():        # 用户可能直接关窗口
        break
    page.wait_for_timeout(300)
    # 回写步数到悬浮条
    page.evaluate("(n) => window.__atpRecorder && window.__atpRecorder.setCount(n)", len(self.events))
    # 每 ~2s 发一次 record.progress，顺便续租
    # 每 ~2s 查一次控制面的停止标志
```

两个细节：

- **续租**：`Run.lease_expires_at` 在收到事件时才刷新（见 `api.py` 的 `ingest_events`）。
  录制可能持续十几分钟，不定期发事件的话租约会过期、任务被回收。`record.progress` 兼做心跳。
- **硬上限**：录制最长 30 分钟，到点强制结束，避免执行器被一个忘了关的窗口占死。

#### 停止的两条路径

1. 页面悬浮条上的「结束录制」→ `emit({type:'stop'})` → binding handler 置 `self._stopped = True`
2. 控制台上的「结束录制」按钮 → 控制面置标志 → 执行器轮询到

**两条都要有**：浏览器窗口可能被挪到别的屏幕、或者已经崩了，得有个后路。

#### summary 形状

```python
{
  "steps": [...],           # compile_events 的产物
  "notes": [...],           # 提示文案
  "raw_event_count": 42,
  "start_url": "...",
  "site_id": "...",
  "credential_id": "...",   # 保存 flow 时要原样带上，否则回放不会登录
  "screenshot": "/artifacts/..."
}
```

## 3. 已知的坑

这些都是踩出来的，别再踩一遍。

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| **单页应用渲染滞后** | `networkidle` 已经返回，2~3 秒后表单才出现；找元素间歇性扑空 | 用 `wait_for_app_ready()`（等到出现可交互元素）。`goto` 动作里已经自动调了 |
| **登录成功不能靠 `load` 事件** | 单页应用登录后不触发整页导航，`load` 立刻返回，**密码错了也会被当成登录成功** | 已改为等「密码框消失」（`waitFor condition=hidden`） |
| **导航清空 window** | 页面内攒的事件丢失 | `expose_binding`（context 级，跨导航存活）+ `add_init_script` |
| **Playwright 浏览器版本绑死** | 报 `Executable doesn't exist at ...headless_shell.exe` | 1.49.1 只认 `chromium-1148`。在项目 venv 里跑 `playwright install chromium`。注意 `PLAYWRIGHT_BROWSERS_PATH` 一旦被设过，换个终端就找不着 |
| **PowerShell 中文乱码** | `Select-String` 匹配中文失败、`python -c` 里带中文报解析错 | 别用 `python -c` 写多行带中文的脚本，写成 `.py` 文件再跑；先设 `$env:PYTHONIOENCODING="utf-8"` |
| **租约超时** | 长时间不上报事件，任务被回收 | 定期发 `record.progress` |
| **`create_all` 不迁移** | 加了字段但表没变 | 开发期删 `var/control.db` 重建 |
| **执行器加载的是旧代码** | 改完代码行为没变 | 执行器是常驻进程，改完必须重启 |

## 4. 验收标准

按顺序验，前面不过别做后面。

1. **编译器自测通过**：`python scripts\selftest_compiler.py`
2. **能录**：控制台发起录制 → 弹出浏览器 → 自动登录进 MES → 右上角出现悬浮条 → 手工点几下、填几个字 → 步数在涨
3. **能停**：点悬浮条上「结束录制」→ 控制台出现步骤列表
4. **步骤是干净的**：填一个输入框只产出**一条** `fill`（不是每个字符一条）；
   点进输入框那一下没有变成独立步骤
5. **能存**：编辑几条 label、加一条断言 → 保存成功 → 流程下拉框里出现
6. **能回放**：勾「开窗执行」跑这条流程 → 它自己登录、自己重复你刚才的操作 → 通过
7. **不支持的操作有提示**：录制时拖一下，确认结果里有「拖拽操作没有被录上」的提示

第 6 条是真正的验收：**录出来的东西必须能自己跑一遍**。

## 5. 明确不做

写进代码注释，别让后来的人以为是漏了：

- **不接大模型**。语义命名、断言、参数化全是规则驱动或人工填。AI 编译是 P1.2
- **不做参数化**。录制时填的值原样保存。后果是第二次回放可能撞唯一性校验——
  这是**已知限制**，在确认界面上提示用户「唯一性字段建议手工改成每次不同的值」，
  P1.2 才做 `{{unique:xxx}}`
- **不做智能等待推断**。步骤之间不自动插 `waitFor`，靠 Playwright 的自动等待和
  `goto` 里的就绪判定顶着。不够用再说
- **不支持**：拖拽排序、canvas、原生文件选择框、跨域 iframe、富文本编辑器内部操作、
  手写签名/滑块。检测到就提示，不产出似是而非的步骤
- **不做录制过程中的 HAR 抓取**。上层设计里有，但那属于 P1.2 和接口引擎的交叉部分
